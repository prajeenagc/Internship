# Week 3 - Database Integration and SQLAlchemy

## Overview

This repository contains my Week 3 backend development internship exercises. The focus is on integrating databases with FastAPI, understanding SQLAlchemy ORM, designing relational database structures, implementing database operations, separating database logic into repository modules, managing database migrations using Alembic, and writing SQL queries for data retrieval and performance optimization.

The week progresses from connecting FastAPI applications to databases and implementing relational models to working with database migrations, joins, indexes, activity tracking, and building a database-backed REST API.

## Learning Objectives

- Understand SQLAlchemy and Object Relational Mapping (ORM).
- Connect FastAPI applications to relational databases.
- Configure database connections using environment variables.
- Create SQLAlchemy models and database tables.
- Understand primary keys, foreign keys, and relational constraints.
- Implement database CRUD operations using SQLAlchemy sessions.
- Separate database operations into repository modules.
- Understand database migrations using Alembic.
- Perform schema upgrades and downgrades.
- Write SQL queries using filtering, sorting, and joins.
- Understand database indexing and query performance.
- Implement activity tracking using database transactions.
- Handle database integrity errors and connection failures.
- Integrate PostgreSQL with FastAPI to build a database-backed REST API.

## Day 11 - SQLAlchemy Introduction and Relational Database Models

**Objective:** Understand SQLAlchemy ORM, connect FastAPI to a relational database, and implement database operations using SQLAlchemy sessions.

### Activities

- Understand the role of SQLAlchemy ORM.
- Configure database connections using `create_engine()`.
- Create a SQLAlchemy declarative base using `declarative_base()`.
- Configure database sessions using `sessionmaker()`.
- Implement database session management using `get_db()`.
- Create SQLAlchemy models for users, projects, project members, and tasks.
- Define primary keys and foreign key relationships.
- Implement database constraints using `CheckConstraint` and `PrimaryKeyConstraint`.
- Understand cascading behaviors such as `CASCADE`, `RESTRICT`, and `SET NULL`.
- Create database tables using `Base.metadata.create_all()`.
- Implement database-backed POST and GET endpoints.
- Use SQLAlchemy queries to create and retrieve records.
- Validate related records before inserting new data.

### Expected outcome

A FastAPI application connected to a relational database using SQLAlchemy, with database models representing users, projects, project members, and tasks. The application supports basic database operations and demonstrates relational database constraints.

## Day 12 - Repository Pattern and Database Operations

**Objective:** Understand the repository pattern and separate database operations from API route handlers.

### Activities

- Organize database configuration into separate modules.
- Configure database settings using Pydantic Settings.
- Load database connection details from environment variables.
- Configure SQLAlchemy engine and session management.
- Create SQLAlchemy models for database entities.
- Implement a separate repository module.
- Move task creation logic into repository functions.
- Implement task retrieval using SQLAlchemy queries.
- Pass database sessions from FastAPI routes to repository functions.
- Use `db.add()` to add new records.
- Use `db.commit()` to persist database changes.
- Use `db.refresh()` to retrieve updated database records.
- Implement transaction rollback using `db.rollback()` when database operations fail.

### Expected outcome

A FastAPI application with database operations separated into a reusable repository module. API routes handle incoming requests while repository functions manage database interactions.

## Day 13 - Database Migrations Using Alembic

**Objective:** Understand database schema migrations and manage database structure changes using Alembic.

### Activities

- Understand the purpose of database migrations.
- Install and initialize Alembic.
- Understand the Alembic project structure.
- Configure `alembic.ini`.
- Configure Alembic's `env.py` file.
- Connect Alembic to SQLAlchemy model metadata.
- Understand the role of `target_metadata`.
- Generate an initial migration for creating an employees table.
- Understand autogenerated migration scripts.
- Implement schema changes by adding a department column.
- Execute database migrations using Alembic.
- Understand migration revision IDs and revision dependencies.
- Apply schema changes using `upgrade()`.
- Reverse schema changes using `downgrade()`.
- Understand how Alembic tracks database schema versions.

### Expected outcome

An Alembic migration environment capable of creating database tables and applying subsequent schema changes. The exercise demonstrates how database structures can be updated and rolled back using migration scripts.

## Day 14 - Advanced SQL Queries, Indexing, and Activity Tracking

**Objective:** Understand relational SQL queries, improve database query performance, and implement activity tracking using SQL.

### Activities

- Create relational database tables using SQL.
- Insert sample users, projects, and tasks.
- Retrieve records using `SELECT`.
- Filter records using `WHERE`.
- Sort records using `ORDER BY`.
- Retrieve related data using `INNER JOIN`.
- Understand the difference between `INNER JOIN` and `LEFT JOIN`.
- Join users, projects, and tasks to retrieve related information.
- Understand database indexing and its purpose.
- Generate synthetic database records for performance testing.
- Insert large amounts of sample data using `generate_series()`.
- Analyze query execution plans using `EXPLAIN ANALYZE`.
- Compare query performance before and after creating an index.
- Inspect database indexes using PostgreSQL system views.
- Create a task activity table to track changes.
- Implement foreign key constraints for activity records.
- Use SQL transactions with `BEGIN` and `COMMIT`.
- Understand Common Table Expressions (CTEs) using `WITH`.
- Use `UPDATE ... RETURNING` to retrieve updated records.
- Record task status changes in an activity table.
- Retrieve activity history using SQL joins.

### Expected outcome

A practical understanding of SQL querying, relational joins, indexing, and database performance analysis. The exercise also demonstrates how task status changes can be recorded in an activity table using SQL transactions and Common Table Expressions.

## Day 15 - PostgreSQL Integration and Database-Backed REST API

**Objective:** Build a database-backed FastAPI application using PostgreSQL, SQLAlchemy, Pydantic schemas, and Alembic migrations.

### Activities

- Configure database settings using Pydantic Settings.
- Load database connection details from an environment file.
- Configure SQLAlchemy engine with `pool_pre_ping=True`.
- Implement reusable database session management.
- Create SQLAlchemy models for users, projects, and tasks.
- Define primary keys, foreign keys, and unique constraints.
- Implement database-level defaults and timestamp fields.
- Create Pydantic request and response schemas.
- Validate incoming data using `Field()` and `EmailStr`.
- Use `ConfigDict(from_attributes=True)` for ORM response serialization.
- Implement user creation and retrieval endpoints.
- Implement project creation and retrieval endpoints.
- Implement task creation, retrieval, updating, and deletion.
- Implement partial updates using PATCH.
- Use `model_dump(exclude_unset=True)` to retrieve explicitly provided update fields.
- Validate referenced users and projects before creating or updating tasks.
- Handle duplicate records using `IntegrityError`.
- Implement database rollback when integrity errors occur.
- Return appropriate HTTP status codes, including 404 and 409.
- Implement a database health-check endpoint using `SELECT 1`.
- Handle database connection failures using SQLAlchemy exceptions.
- Configure Alembic for the application database.
- Create an initial migration for users, projects, and tasks.
- Define database constraints and indexes through migration scripts.
- Implement a database seeding script to insert sample users, projects, and tasks.
- Use transaction rollback and session cleanup in the seeding process.

### Expected outcome

A database-backed FastAPI REST API integrated with PostgreSQL and SQLAlchemy. The application supports user, project, and task management, database validation, integrity error handling, health checks, schema migrations, and sample data seeding.
